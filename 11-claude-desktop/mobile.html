Claude Desktop

The Native Claude App

One window, three tabs — Chat, Code, and Cowork — plus a global hotkey, tray icon, connectors, and native notifications.

Native App Chat Code Cowork
01

What Is It?

Claude Desktop is the native app for Claude on macOS and Windows. A signed-in wrapper around claude.ai with system integration a browser can’t give you.

Chat

  • Conversation, Projects, Artifacts
  • Files, images, voice
  • Extended thinking, Styles

Cowork

  • Autonomous background agent
  • Runs in a cloud sandbox (or a local VM)
  • Steer from web or phone

Code

  • Interactive pair programming
  • Local files, visual diffs
  • Same engine as the CLI

Why native? Global hotkey, menu-bar/tray icon, drag-and-drop, native notifications, and installable MCP connectors.

Rule of thumb: Desktop for one window with OS integration; Web on a machine you don’t control; CLI in a terminal or scripts. Same account across all three.

Windows: Early-2026 Caveat

Early-2026 docs: the MSIX installer sandboxed Desktop. CLI (PowerShell) writes to %USERPROFILE%\.claude.json; Desktop reads from a virtualized path. claude mcp add does not reach Desktop. Add MCP servers through the Desktop UI. WSL2 adds a third separate config. On macOS, CLI and Desktop share config seamlessly.

Config by Platform

macOS

  • Chat MCP: ~/Library/Application Support/Claude/claude_desktop_config.json
  • Code CLI / Code tab: ~/.claude.json + .mcp.json
  • Settings: ~/.claude/settings.json
  • Logs: ~/Library/Logs/Claude/

Windows (CLI paths)

  • Chat MCP: %APPDATA%\Claude\claude_desktop_config.json
  • Code CLI: %USERPROFILE%\.claude.json + .mcp.json
  • Settings: %USERPROFILE%\.claude\settings.json
  • Logs: %APPDATA%\Claude\logs\

Linux

  • Desktop app in beta (apt)
  • Code CLI: ~/.claude.json + .mcp.json
  • Settings: ~/.claude/settings.json
  • Debug logs: ~/.claude/debug/

Windows: MSIX (early-2026 docs)

Early-2026 docs: Desktop’s MSIX package virtualized its filesystem. CLI paths above are what the CLI reads — Desktop reads from %LOCALAPPDATA%\Packages\Claude_…\. claude mcp add does not reach Desktop. WSL2 adds a third config surface. Use the Desktop UI for MCP on Windows.

All Platforms

Project instructions: CLAUDE.md / CLAUDE.local.md in project root. Project MCP: .mcp.json in project root.

11

MCP Transports

Three transports: stdio (local subprocess), Streamable HTTP (current remote standard), and deprecated HTTP+SSE.

stdio

  • Subprocess on your machine, stdin/stdout
  • Works on: CLI, Chat tab, Code tab
  • Cannot reach the network

Streamable HTTP

  • Single HTTP(S) endpoint, POST + optional SSE
  • Current standard (March 2025 spec)
  • CLI + Code tab → plain HTTP + private IPs OK
  • Chat tab config → stdio only; use Connectors or mcp-remote proxy
  • Cowork, Web, Mobile, API → public HTTPS URL

Private Network

CLI + Code tab: plain HTTP and LAN IPs work (http://10.60.12.34:3001/mcp). Chat tab: stdio config only; use mcp-remote proxy for remote. Brokered surfaces need public HTTPS.

Config Gotcha

Chat tab → claude_desktop_config.json. Code tab → ~/.claude.json. Separate — servers don’t cross.

Troubleshooting

Sign-in Loops

  • Quit fully, relaunch, sign in again
  • Clear OAuth from the keychain
  • 403 → sign out from app menu

Cowork Missing

  • New experience: no Cowork tab, just ask
  • Free plans: no Cowork
  • Local sessions: check virtualisation

Connectors

  • Local ones need the target app installed
  • Remote ones need OAuth
  • Corporate firewall may block MCP WebSocket

Logs

  • ~/Library/Logs/Claude (mac)
  • %APPDATA%\Claude\logs (win)
  • Help → Send Feedback attaches them
