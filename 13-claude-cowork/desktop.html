Claude Cowork

Hand Claude a whole task; it works in an isolated sandbox and hands back finished work

Cowork brings Claude Code’s agentic architecture to everyday knowledge work, with no terminal. Since September 2026 it is part of one Claude: describe an outcome in any conversation and Claude plans the work, runs code in a sandbox, reaches only the folders you connect, and returns documents, spreadsheets and decks. On Pro and Max, new tasks have run in the cloud since 6 October 2026.

One Claude Cloud Sandbox Your Folders Scheduled Tasks

Based on the Cowork articles on support.claude.com and the Cowork docs on claude.com/docs, checked October 2026

01

What Cowork Is Now

Cowork uses the same agent loop as Claude Code, aimed at work beyond coding. Instead of answering one prompt at a time, Claude takes an outcome, plans the steps, and works through them: searching, reading your files, running code, and assembling the result.

What It Does

  • Describe an outcome, step away, and come back to finished work
  • Splits complex work into sub-agents that run in parallel
  • Runs code and shell commands in an isolated environment, never on your bare machine
  • Delivers real files: Excel with working formulas, PowerPoint decks, formatted documents
  • Reads and writes local folders you connect, through the desktop app

How It Is Presented Now

  • “Cowork is now Claude” (16 Sep 2026): chat and Cowork become one conversation
  • No mode to pick: a quick question gets a quick answer; a task becomes a Cowork session
  • Until an account moves over, the message box still shows Chat and Cowork
  • Tasks sit with chats in Recents; Code stays a separate tab

How It Differs from Chat and from Claude Code

Chat and Cowork are now one conversation. It starts as a chat; when a task needs to run code or work with files, Claude continues the same conversation in a Cowork session, then goes back to chat when it doesn’t. A quick question still gets a quick answer. The real choice left is between Cowork and Claude Code.

04

A Worked Task, Start to Finish

One of Anthropic’s own examples: drop receipts in a folder and ask for an expense report. The steps below follow the documented flow; the wording is illustrative.

1 · Connect a folder

  • In Claude Desktop, give Claude access to ~/Expenses/October
  • It appears under Trusted folders; Claude can read and write only there

2 · Describe the outcome

  • Say what you want, the format, and the inputs, as you would brief a colleague
  • “Turn these receipts into a spreadsheet: one row each, totals by category.”

3 · Choose how it checks in

  • Auto (default on Pro, Max, Team): actions are screened and unsafe ones blocked
  • Manual (default on Enterprise): you allow or deny each action

4 · Claude plans and runs

  • Plans, splits into sub-agents if useful, and runs its code in the sandbox
  • Fetches a copy of each receipt it needs through the desktop app

5 · Steer from anywhere

  • Progress shows each step; jump in to redirect at any time
  • Open the same session on your phone to answer a question; you get a notification when it’s done

6 · Get the file, then repeat it

  • The spreadsheet appears beside the conversation: preview, download, or ask for changes
  • Make it recurring: “Every Monday at 9 AM, add last week’s receipts.”

Before you press send: deleting files always needs your explicit Allow, in every mode. For anything with real consequences — money, messages sent as you, important files — Anthropic advises staying close or switching to Manual.

05

How It Runs — A Cloud Sandbox, Your Computer on a Leash

On Pro and Max, every new task runs in the cloud; Team runs there by default and Enterprise when an owner turns it on. The agent loop and code run on Anthropic’s servers; your computer joins only through the desktop app.

Keeps Going

Close the laptop and the task continues; the result waits in the conversation. Scheduled tasks need no device online.

Isolation Has Limits

It keeps Claude’s code off your machine and network. It does not limit what Claude can read or do through the access you grant.

Your Data

Sessions and files live in your Claude account. Team and Enterprise data isn’t used for training; on consumer plans your privacy setting decides.

06

Local Mode — The VM on Your Device

Cowork began as a desktop feature that ran on your computer, and that design still exists. A local session runs the agent loop natively and puts code inside a Linux virtual machine that the desktop app hosts.

Who Still Runs Locally

  • Pro and Max: only tasks and scheduled tasks started on the device before 6 Oct 2026
  • Team and Enterprise: local sessions remain; Enterprise has cloud sessions off until an owner turns them on
  • HIPAA-ready Enterprise with the local-mode configuration (cloud unavailable)
  • Claude Desktop on 3P (your own cloud inference provider)

What the VM Needs

  • Linux: KVM enabled in firmware, your user in the kvm group, QEMU (apt pulls it in), ~25 GB free disk, 8 GB RAM; the workspace uses 4 GB while running
  • macOS / Windows (per the Desktop on 3P guide): macOS 14+ on Apple silicon or Intel; Windows 10 build 19041+ on x64 or Arm64, the .msix installer, and the Virtual Machine Platform feature

How It Behaves

  • The app must stay open and the computer awake, or the session may end
  • If the VM can’t start, file and web tools keep working; shell reports “workspace unavailable”
  • History is stored on the computer, outside Anthropic’s retention; admins can’t delete it centrally
07

Files, Folders, and Permissions

Files and Folders

  • Claude reads and writes only folders you connect (listed under Trusted folders)
  • A cloud session reaches them only while the desktop app is open, and only if the session began on desktop or is a scheduled task
  • It fetches a copy of just the file it needs; deleting the session deletes the copies
  • Folder instructions add context for a folder; Claude can update them itself
  • Files Claude makes appear beside the conversation; on desktop the old Cowork output folder is the Storage folder in Settings

Always Asks First

Permanently deleting a file always needs your explicit Allow, whatever the mode. Keep a dedicated working folder and backups rather than granting broad access.

Permission modes × connector tool settings

  • Auto reviews every action for exfiltration and prompt injection and blocks unsafe ones; after repeated blocks it falls back to asking
  • Skip all approvals has no such check: only for tasks where you trust every tool, file and site
  • New experience: the message box offers Auto (default on Pro, Max, Team) and Manual (default on Enterprise)

Why Injection Needs Two Things

A prompt injection succeeds only when Claude can read content from outside your trust boundary and can take actions that hurt you. Remove either and the attack gets much harder: limit untrusted sites, or limit write tools.

08

Connectors, MCP, Plugins, and the Browser

Claude picks the most precise tool first, and falls back only when it has to:

Connectors (Remote MCP)

  • Add from the Connectors Directory or by a server’s HTTPS URL, under Customize → Connectors; the same connectors serve chat, Cowork and Claude Code
  • In cloud sessions the calls are made server-side; connector tokens never enter the sandbox
  • A server inside a private network isn’t reachable directly; Enterprise can request MCP tunnels (research preview)

Local MCP Servers

  • Desktop extensions (.mcpb) and plugin-bundled local servers run on your computer, through the desktop app only
  • They never run inside a cloud sandbox
  • Managed devices can turn them off: isLocalDevMcpEnabled, isDesktopExtensionEnabled

Skills and Plugins

  • A plugin bundles skills, connectors and sub-agents; it is saved to your account and works in chat, Cowork and Claude Code
  • Cowork loads what Customize enables, synced at session start; it doesn’t read the CLI’s ~/.claude

The Browser

  • Built-in browser in a side panel of the desktop app (the default); or your own Chrome through Claude in Chrome
  • Logins import site by site; banking, email and single sign-on stay unchecked by default
  • Asks before acting on a site for the first time; high-risk sites are blocked
  • Traffic comes from your machine, even when you steer from the web or your phone
09

Long-Running and Scheduled Work

Long-Running Tasks

  • Work on complex tasks for long periods without conversation timeouts or context limits getting in the way
  • Cloud sessions keep going with the laptop closed or the page left
  • Several tasks can run at the same time

Scheduled Tasks (All Paid Plans)

  • Say it in any conversation: “Every weekday at 8 AM, summarise new messages in my team’s Slack channels”, then review and click Schedule
  • Or Scheduled → New task: name, prompt, approval mode, frequency (hourly, daily, weekly, weekdays, or manual), optional model and folder
  • Each run is its own session; past and upcoming runs are on the Scheduled page on any surface
  • They run in the cloud with no device online — except tasks that need local files or apps, which run only locally

Unwatched Means Careful

  • Start with low-risk summaries before automating anything more
  • Don’t schedule tasks that touch sensitive files, send messages as you, or buy things
  • Review the output of each run; pause or delete tasks you no longer use
  • You remain responsible for what a scheduled task does on your behalf

Dispatch (Winding Down)

  • One persistent thread from phone to desktop: the work runs on your computer, so it must stay awake with the app open
  • Routes coding to Claude Code and knowledge work to Cowork
  • Limited beta on some Pro and Max plans; not available to new users — cloud sessions replace it

Phone: a task started at your desk appears in Claude mobile; you get a notification when it finishes or needs input.

12

Limits and Gotchas

Limits

  • Paid plans only; the Free plan has no Cowork
  • Sessions can’t be shared; share the artifacts they produce instead
  • Computer use is a beta for Pro and Max on macOS and Windows only: not on Linux, not on Team or Enterprise
  • Multi-step tasks use more of your plan’s usage than a quick question; check Settings → Usage
  • On Pro and Max there is no setting for where a task runs, and no way back to local
  • Live artifacts made before 19 Aug 2026 work on desktop only and can’t be edited in place

New-Experience Gaps

  • No “Add from GitHub”; no branching from an earlier point
  • Incognito chats open in the old experience, without files or code
  • Search skips older Cowork tasks; find them by name in Recents

Gotchas

  • Desktop app closed? A cloud task keeps running, but can’t reach your folders, browser or apps
  • Network egress settings don’t cover web search, web fetch or MCP connectors, including Claude in Chrome
  • Egress changes apply to new sessions only; start a new conversation
  • Anything you sign in to in the built-in browser is available to Claude in later sessions on that computer
  • Computer use takes screenshots; a link it clicks opens even in an app you didn’t allow
  • Skills that live only in ~/.claude don’t appear until you add them in Customize
  • “Setting up Claude’s workspace” is normal: Cowork is updating

If something looks off — Claude reaching for files or sites you didn’t mention, or the task drifting — stop it, then report it with the in-app feedback button.
